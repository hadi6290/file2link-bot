# 🤖 ربات File2Link تلگرام
### نسخه بدون VPS، بدون کارت بانکی — فقط Cloudflare Workers Free + KV Free

---

## ⚠️ یک تغییر مهم نسبت به درخواست اولیه (حتماً بخوان)

در درخواست اولیه، پوشه‌ای جدا برای ربات (`bot/` با `npm start` و Telegraf) در نظر گرفته شده بود
که باید همیشه در حال اجرا باشد (polling). **این با محدودیت «بدون VPS» در تناقض است**، چون یک
پروسه‌ی Node.js که باید ۲۴ ساعته روشن بماند، به یک سرور نیاز دارد.

راه‌حل واقعی و رایگان: **کل ربات و کل دانلودر در یک Cloudflare Worker واحد** اجرا می‌شود و با
تلگرام از طریق **Webhook** (نه polling) صحبت می‌کند. Telegram خودش هر پیام جدید را با یک
درخواست HTTP به آدرس Worker شما ارسال می‌کند — پس هیچ پروسه‌ی همیشه‌روشنی لازم نیست.

به همین دلیل هم به‌جای کتابخانه Telegraf (که برای Node.js طراحی شده) از فراخوانی مستقیم
Telegram Bot API با `fetch` استفاده شده — سبک‌تر، بدون هیچ وابستگی npm، و کاملاً سازگار با
Workers runtime.

**نتیجه: پروژه دقیقاً همان محدودیت‌های تو را رعایت می‌کند — فقط Cloudflare Workers Free و
Cloudflare KV Free، بدون VPS، بدون کارت بانکی، ۱۰۰٪ رایگان.**

## 1️⃣ معماری پروژه

```
کاربر تلگرام
     │  فایل ارسال می‌کند
     ▼
Telegram Bot API  ──── Webhook (POST) ───▶  Cloudflare Worker (/webhook)
                                                   │
                                                   │ توکن کوتاه تولید می‌کند
                                                   │ اطلاعات فایل را در KV ذخیره می‌کند
                                                   ▼
                                             Cloudflare KV
                                          (فقط متادیتا، نه خودِ فایل)
                                                   │
کاربر لینک را دریافت می‌کند                        │
     │                                             │
     ▼                                             │
مرورگر  ── GET /d/:token ──▶  Cloudflare Worker ◀──┘  (رندر صفحه HTML دانلود)
     │
     ▼
مرورگر  ── GET /download/:token ──▶  Cloudflare Worker
                                            │
                                            │ getFile (Telegram Bot API)
                                            ▼
                                     Telegram File Servers
                                            │
                                            │ استریم مستقیم (بدون ذخیره روی دیسک)
                                            ▼
                                     دانلود در مرورگر کاربر
```

نکته کلیدی: **فایل هیچ‌وقت روی سرور شما ذخیره نمی‌شود.** Worker فقط `file_id` را در KV نگه
می‌دارد و در لحظه‌ی دانلود، محتوای فایل را از سرورهای تلگرام مستقیماً به کاربر استریم می‌کند
(pass-through)، بدون بافر کردن کامل فایل در حافظه.

### محدودیت ذاتی مهم (از طرف خودِ تلگرام، نه Cloudflare)
Telegram Bot API به هیچ رباتی اجازه دانلود فایل‌های **بزرگ‌تر از 20 مگابایت** را نمی‌دهد
(این محدودیت مستقل از سرور شماست و فقط با Local Bot API Server خودمیزبانی‌شده — که یعنی VPS —
قابل دور زدن است). ربات این محدودیت را پیش از تولید لینک بررسی و به کاربر اطلاع می‌دهد.

## 3️⃣ ساخت ربات با BotFather (کاملاً با گوشی اندروید)

1. اپلیکیشن Telegram را باز کن و در جستجو بنویس: `BotFather` (اکانت آبی‌تیک با یوزرنیم
   `@BotFather`).
2. دستور `/newbot` را بفرست.
3. یک **نام نمایشی** برای ربات انتخاب کن (مثلاً: `File2Link Bot`).
4. یک **یوزرنیم** انتخاب کن که حتماً به `bot` ختم شود (مثلاً: `myfile2link_bot`).
5. BotFather یک پیام حاوی **توکن** برمی‌گرداند، شبیه به:
   `123456789:AAHk3jak3nDkeoaKLxxxxxxxxxxxxxxx`
   این توکن را جایی امن کپی کن — همان `BOT_TOKEN` است.
6. (اختیاری، فقط اگر می‌خواهی ربات در گروه‌ها هم فایل‌های ارسالی را ببیند)
   دستور `/setprivacy` را بفرست، ربات خودت را انتخاب کن، و گزینه `Disable` را بزن.
   برای چت خصوصی (که سناریوی اصلی این پروژه است) نیازی به این مرحله نیست.
7. یوزرنیم ربات (`@myfile2link_bot`) همان چیزی است که کاربران برای شروع چت با ربات استفاده
   می‌کنند.

## 4️⃣ ساخت Cloudflare Worker + KV (کاملاً با گوشی اندروید، بدون نیاز به Termux)

### روش پیشنهادی: مستقیم از طریق داشبورد Cloudflare در مرورگر گوشی

1. در مرورگر گوشی برو به `dash.cloudflare.com` و ثبت‌نام کن (رایگان، بدون کارت بانکی).
2. از منو: **Workers & Pages → Create → Create Worker**. یک نام بده (مثلاً `file2link-bot`)
   و Deploy کن (نسخه پیش‌فرض).
3. برو به **Workers & Pages → KV → Create a namespace**، نام بگذار `LINKS` و بساز.
4. برگرد به Worker ساخته‌شده → تب **Settings → Bindings → Add binding → KV Namespace**:
   - Variable name: `LINKS`
   - KV namespace: همان `LINKS` که ساختی
   - Save.
5. باز هم در **Settings → Variables and Secrets**:
   - یک Secret با نام `BOT_TOKEN` بساز و توکن دریافتی از BotFather را وارد کن.
   - یک Secret دیگر با نام `WEBHOOK_SECRET` بساز و یک رشته تصادفی دلخواه (مثلاً چند کلمه
     بی‌معنی) وارد کن. این فقط برای امنیت اضافه است تا کسی نتواند مستقیم به `/webhook` شما
     درخواست جعلی بفرستد.
6. برو به تب **Edit Code** (یا Quick Edit) و محتوای فایل‌های داخل `worker/src/` را در Worker
   قرار بده. اگر ادیتور داشبورد فقط از یک فایل پشتیبانی می‌کند، محتوای `index.js`، `bot.js`،
   `telegram.js`، `download.js`، `pages.js` و `utils.js` را به‌ترتیب import در یک فایل واحد
   ادغام کن (import ها را حذف و کدها را پشت سر هم بچسبان) — یا از روش CLI زیر استفاده کن که
   ساختار چندفایلی را بدون تغییر می‌پذیرد.
7. **Deploy** بزن. آدرس نهایی چیزی شبیه این خواهد بود:
   `https://file2link-bot.YOUR-SUBDOMAIN.workers.dev`

### روش جایگزین: با ترمینال (اگر روی گوشی Termux نصب داری)

```bash
# نصب وابستگی‌ها
cd telegram-file2link/worker
npm install

# ورود به حساب Cloudflare (یک لینک باز می‌شود، در مرورگر گوشی تایید کن)
npx wrangler login

# ساخت KV Namespace
npx wrangler kv namespace create LINKS
# خروجی چیزی شبیه این می‌دهد:
#   id = "abcd1234efgh5678..."
# این id را داخل wrangler.toml جایگزین PUT_YOUR_KV_NAMESPACE_ID_HERE کن

# تنظیم Secret ها (توکن هیچ‌وقت داخل کد یا wrangler.toml نوشته نمی‌شود)
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET

# دیپلوی نهایی
npx wrangler deploy
```

پس از دیپلوی، آدرس Worker (مثل `https://file2link-bot.your-subdomain.workers.dev`) در خروجی
ترمینال چاپ می‌شود.

## 5️⃣ اتصال ربات به Worker (تنظیم Webhook)

این کار فقط یک درخواست HTTP ساده است و می‌توانی آن را **مستقیم در مرورگر گوشی** با تایپ آدرس
زیر انجام دهی (به‌جای Termux/curl):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<WORKER_URL>/webhook&secret_token=<WEBHOOK_SECRET>
```

مقادیر را جایگزین کن:
- `<BOT_TOKEN>` → توکنی که از BotFather گرفتی
- `<WORKER_URL>` → آدرس Workerت (بدون `https://` تکراری)
- `<WEBHOOK_SECRET>` → همان رشته‌ای که به‌عنوان Secret ست کردی

مثال واقعی:
```
https://api.telegram.org/bot123456789:AAHk3.../setWebhook?url=https://file2link-bot.myname.workers.dev/webhook&secret_token=my-super-secret-123
```

اگر پاسخ `{"ok":true,"result":true,"description":"Webhook was set"}` را دیدی، یعنی موفق بوده.

برای بررسی وضعیت Webhook در هر لحظه:
```
https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo
```

برای حذف Webhook (مثلاً هنگام دیباگ محلی):
```
https://api.telegram.org/bot<BOT_TOKEN>/deleteWebhook
```

## 6️⃣ سناریوی تست کامل

1. در تلگرام، چت با ربات (`@myfile2link_bot`) را باز کن و یک فایل PDF بفرست.
2. باید پیامی شامل نام فایل، حجم فایل، زمان انقضا (۲۴ ساعت) و دکمه «باز کردن صفحه دانلود»
   دریافت کنی.
3. روی دکمه بزن یا لینک را در مرورگر باز کن → باید صفحه دانلود فارسی با شمارنده معکوس نمایش
   داده شود.
4. روی «⬇️ دانلود فایل» بزن → فایل باید با نام صحیح دانلود شود.
5. صفحه را رفرش کن → عدد «تعداد دانلود تاکنون» باید افزایش یافته باشد.
6. برای تست انقضا: مقدار `expire_at` رکورد را در KV (از داشبورد Cloudflare → KV → مرور کلید)
   به یک زمان گذشته دستی تغییر بده و صفحه را دوباره باز کن → باید پیام «لینک منقضی شده» با
   کد وضعیت 410 نمایش داده شود.
7. برای تست 404: یک توکن ساختگی و نامعتبر را در انتهای `/d/` وارد کن → باید پیام «لینک یافت
   نشد» با کد وضعیت 404 نمایش داده شود.

## 7️⃣ نکات امنیتی رعایت‌شده

- **توکن غیرقابل حدس**: تولید با `crypto.getRandomValues` (نه `Math.random`)، طول ۱۰ کاراکتر
  از مجموعه ۶۲ کاراکتری → فضای نمونه حدود ۸۳۹ کوینتیلیون حالت.
- **عدم افشای BOT_TOKEN**: توکن فقط به‌صورت Secret روی Worker ذخیره می‌شود و هرگز در HTML یا
  پاسخ به کلاینت درج نمی‌شود؛ درخواست‌های Telegram API فقط از سمت Worker (سرور) ارسال می‌شوند.
- **انقضای واقعی**: هم در سطح اپلیکیشن (`expire_at` چک می‌شود) و هم در سطح KV
  (`expirationTtl`) — یعنی حتی اگر چک برنامه فراموش شود، KV خودش کلید را حذف می‌کند.
- **Rate Limiting**: حداکثر ۱۵ درخواست دانلود در دقیقه به‌ازای هر IP روی هر توکن، با شمارنده
  موقت در KV.
- **Webhook Secret**: مسیر `/webhook` فقط درخواست‌هایی را می‌پذیرد که هدر
  `X-Telegram-Bot-Api-Secret-Token` با مقدار تنظیم‌شده مطابقت داشته باشد — از جعل درخواست به
  Worker شما جلوگیری می‌کند.
- **هدرهای دانلود صحیح**: `Content-Disposition`, `Content-Type`, `Cache-Control: no-store`.
- **جلوگیری از XSS**: نام فایل قبل از درج در HTML با `escapeHtml` پاک‌سازی می‌شود.

## 8️⃣ محدودیت‌های پلن رایگان Cloudflare (حتماً بدان)

| مورد | محدودیت رایگان |
|---|---|
| درخواست‌های Worker | ۱۰۰,۰۰۰ در روز |
| CPU time هر درخواست | ۱۰ میلی‌ثانیه (محاسبات، نه زمان انتظار I/O مثل fetch) |
| خواندن از KV | ۱۰۰,۰۰۰ در روز |
| نوشتن در KV | ۱,۰۰۰ در روز |
| حذف از KV | ۱,۰۰۰ در روز |
| حجم ذخیره‌سازی KV | ۱ گیگابایت |
| Subrequests هر درخواست | ۵۰ |

نکات عملی:
- هر بار دانلود فایل، ۲ subrequest مصرف می‌کند (`getFile` + دریافت خود فایل) — خیلی دور از
  سقف ۵۰ است.
- سقف «۱,۰۰۰ نوشتن KV در روز» یعنی اگر بیش از حدود ۱۰۰۰ فایل جدید یا ۱۰۰۰ به‌روزرسانی
  شمارنده دانلود در روز داشته باشی، باید به پلن Paid (۵ دلاری) ارتقا بدهی. برای استفاده
  شخصی/کوچک کاملاً کافی است.
- محدودیت ۲۰ مگابایتی فایل، محدودیت Telegram Bot API است، نه Cloudflare.

## 9️⃣ توسعه‌های آینده پیشنهادی

1. **لینک با رمز عبور**: افزودن فیلد `password_hash` به رکورد KV؛ قبل از نمایش دکمه دانلود،
   یک فرم رمز عبور نشان بده و فقط بعد از تطبیق هش (مثلاً با Web Crypto `SubtleCrypto.digest`)
   اجازه دانلود بده.
2. **لینک یک‌بارمصرف**: افزودن فیلد `max_downloads: 1`؛ در `handleDownload`، بعد از هر دانلود
   موفق چک کن اگر `downloads >= max_downloads` رکورد را فوراً از KV حذف کن
   (`env.LINKS.delete(token)`).
3. **پوشه اشتراکی (چند فایل زیر یک لینک)**: به‌جای یک `file_id`، یک آرایه از فایل‌ها را زیر
   یک `folder_token` ذخیره کن؛ صفحه `/d/:folder_token` لیستی از فایل‌ها را با دکمه دانلود
   جداگانه برای هرکدام نمایش دهد.
4. **آمار و دشبورد مدیریتی**: یک دستور `/mylinks` در ربات اضافه کن که همه توکن‌های ساخته‌شده
   توسط آن کاربر (با ذخیره `chat_id` در رکورد) و شمارنده دانلود هرکدام را نشان دهد.
5. **زمان انقضای قابل‌تنظیم**: به کاربر اجازه بده با دکمه‌های Inline (۱ ساعت / ۲۴ ساعت / ۷
   روز) زمان انقضا را خودش انتخاب کند.

## 🔑 خلاصه متغیرهای محیطی (Secrets روی Worker)

| نام | توضیح | نحوه تنظیم |
|---|---|---|
| `BOT_TOKEN` | توکن دریافتی از BotFather | `npx wrangler secret put BOT_TOKEN` یا از داشبورد |
| `WEBHOOK_SECRET` | رشته دلخواه برای تایید امنیتی Webhook | `npx wrangler secret put WEBHOOK_SECRET` یا از داشبورد |

و در `wrangler.toml`، Binding نام `LINKS` باید به namespace ساخته‌شده در KV اشاره کند.
